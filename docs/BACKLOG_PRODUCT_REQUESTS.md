## 2. Полный редизайн pipeline обложек (ISBN-first + confidence scoring)

Развёрнутая спецификация от пользователя — переносится сюда дословно по сути,
без сокращений важных решений.

### Сценарий

1. Пользователь фотографирует книгу. Фото выполняет две роли: помогает
   распознать книгу и подтверждает, что экземпляр реально у него есть — но не
   обязано попадать в публичный каталог как есть.
2. Разделить хранение: `originalEvidenceImage` (исходное фото — для OCR и
   модерации, ограниченный срок хранения, видно только владельцу и админу,
   можно удалить после успешного определения издания) и `displayCoverUrl`
   (красивая обложка каталога).
3. Порядок распознавания: сначала ISBN (штрихкод сзади либо OCR на странице
   выходных данных), затем OCR названия/автора/издательства, определение
   языка, визуальное сравнение обложек-кандидатов.
4. Источники обложек по приоритету:
   - **Приоритет 1 (точный ISBN):** Open Library (обложка по ISBN/OLID/OCLC/
     LCCN/Cover ID, `default=false` для честного 404 вместо заглушки) →
     Google Books (уже есть как fallback в проекте — расширить до полного
     сопоставления издания, не «первая картинка»).
   - **Приоритет 2 (метаданные без ISBN):** `title + author + language +
     publisher + publicationYear` через Open Library Search API (издания, не
     произведения); для польских изданий — дополнительно API Biblioteki
     Narodowej (библиографические записи, JSON/XML/MARC) как источник
     подтверждения ISBN/издателя/языка/года (не обязательно источник самой
     обложки).
5. **Язык — жёсткий фильтр, не бонус к рейтингу**: если язык уверенно
   определён OCR (например, польский), обложки на другом языке отбрасываются
   полностью, а не просто получают штраф к score.
6. **Confidence scoring:**

   | Совпадение | Уверенность | Действие |
   |---|---|---|
   | Точный ISBN-13/10 | 100 | автоматически |
   | ISBN + совпал язык | 100 | автоматически |
   | Название+автор+язык+издатель+год | 90–97 | автоматически |
   | Название+автор+язык+визуальное сходство | 82–92 | подтверждение пользователя |
   | Название+автор+язык | 65–80 | на модерацию |
   | Только название+автор | ≤60 | не выбирать автоматически |

   Правило: `>=0.92` авто-выбор, `0.70–0.92` показать 2–4 варианта,
   `<0.70` — обработанное фото или заглушка.
7. **UI подтверждения:** при точном совпадении — карточка «Нашли это издание:
   название, автор, издательство, язык, ISBN» с кнопками «Да, это она» /
   «Выбрать другую» / «Оставить моё фото». При нескольких кандидатах —
   карусель 2–4 вариантов (обложка, язык, издательство, год, ISBN), не больше.
8. **Если красивой обложки нет нигде** — не показывать сырое фото пользователя
   как есть, а очистить его до вида «скана»: найти углы книги, исправить
   перспективу, обрезать фон/руки/стол, поворот, баланс белого, снизить блики,
   сохранить в WebP, поместить в единый фирменный контейнер. Важно для старых
   изданий, белорусских книг, локальных издательств, самиздата, книг без ISBN,
   редких переводов.
9. **«Общий стиль» = рамка вокруг настоящей обложки, не подмена содержания**:
   не перерисовывать обложку и не генерировать AI-обложку (может создать
   несуществующее издание). Единый размер карточки, соотношение сторон,
   кремовый фон, скругление, тень, внутренние поля, `object-fit: contain`,
   плашка языка, одинаковое качество WebP.

### Схема данных (предложение пользователя, ещё не применено)

```prisma
model Book {
  isbn10            String?
  isbn13            String?
  editionLanguage   String?
  publisher         String?
  publicationYear   Int?

  originalPhotoUrl  String?
  coverUrl          String?
  coverSource       String? // openlibrary | google | bn | user_cleaned | manual
  coverSourceId     String?
  coverConfidence   Float?
  coverStatus       String  @default("missing")
  // missing | resolving | auto | review | confirmed | failed

  coverVerifiedAt   DateTime?
  coverVerifiedByTg BigInt?

model CoverCandidate {
  id          String @id @default(cuid())
  bookId      String
  source      String
  sourceId    String?
  url         String

  language    String?

  selected    Boolean @default(false)

}
```

### Backfill для существующей библиотеки (3251 книга)

Очередь по приоритету: (1) книги с ISBN → (2) название+автор+язык →
(3) название+автор без языка → (4) неполные данные. Высокая уверенность —
ставить автоматически, средняя — очередь администратора, низкая — фирменная
заглушка. Ограничить параллелизм и соблюдать rate limit внешних API (Open
Library Covers API — публичный, но массовую обработку всё равно вести
контролируемой очередью, не тысячами одновременных запросов).

### Итоговый pipeline (по описанию пользователя)

```
Фото → приватное исходное фото → поиск barcode/ISBN
  → (найден) exact edition lookup | (не найден) OCR title/author/publisher/language
  → Open Library → Google Books → BN metadata → кандидаты
  → проверка языка и ISBN → confidence
  → (>92% авто) | (70–92% выбор/модерация) | (<70% cleaned photo)
  → thumbnail pipeline (webp) → единая фирменная карточка каталога
```

### Итоговое решение пользователя (как записано в запросе)

ISBN и язык определяют точное издание; Open Library → Google Books → BN
metadata; фото пользователя — доказательство, не основная обложка; при точном
совпадении — официальная обложка издания; при сомнении выбирает
пользователь/админ; если обложки нет — фото чистится до вида скана; общий
стиль — рамка и обработка, не подмена содержания обложки.

**Замечание для реализации (не путать со Stage 3):** это отдельная, гораздо
более крупная работа, чем уже сделанный image resize/cache pipeline (thumb/
card/carousel варианты, sharp-конвейер, SSRF-защита) — тот пайплайн просто
ресайзит и кэширует уже имеющийся `coverUrl`, а этот запрос — про то, ОТКУДА
берётся сам `coverUrl` (ISBN-поиск по внешним каталогам, confidence scoring,
UI подтверждения, backfill). Их не нужно путать при планировании — первый уже
закрыт, второй ещё не начат.

## 4. Рейтинг книги и короткая аннотация после прочтения

Запрос от 29 июля 2026. Оформлен в GitHub Issue
[#18](https://github.com/ipostatos/mnenezhalko/issues/18), здесь — суть и
проектные решения, которые в issue заданы как обязательные.

Формулировка заказчика: «рейтинг книги появляется после того, как прочитал.
Можно поставить рейтинг и написать короткую аннотацию, её видят все».

- **Право на отзыв даёт факт прочтения**, а не наличие аккаунта: закрытая
  выдача этой книги на человека (`Loan.status='returned'`) либо кнопка
  «Прочитал» на собственной полке. Иначе оценки накручиваются.
- **Спрашиваем один раз**, сразу после подтверждения возврата: 5 кнопок
  ★1–★5, затем предложение написать 1–2 предложения (до 300 знаков) или
  пропустить. Свой отзыв редактируется и удаляется в Mini App.
- **Рейтинг вешается на произведение, а не на экземпляр.** У одной книги в
  каталоге несколько карточек (у каждого библиотекаря своя): при привязке к
  `Book.id` у трёх экземпляров будет три разных рейтинга по одной оценке.
  Ключ группировки — нормализованный `search` (title + author), тот же, что в
  проверке дублей.
- **Публичный текст требует модерации.** MVP: постмодерация, кнопка
  «пожаловаться», авто-скрытие после N жалоб, запрет ссылок в тексте.
  Подпись автора — по правилам приватности контактов (tgId не отдаём, ник
  только если человек его показывает).
- **В Notion отзывы не пишем.** Источник правды по книгам — общая таблица
  заказчика, но отзывы это не данные каталога. Если они там понадобятся, это
  отдельная таблица, а не колонка в книгах.
- **Агрегаты денормализуются** (`ratingAvg`, `ratingCount`) и пересчитываются
  в одной транзакции с отзывом, иначе сортировка по рейтингу будет считать
  весь каталог на каждый запрос.
