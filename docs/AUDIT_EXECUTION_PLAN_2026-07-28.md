## Риски и план миграций

- **Миграции Prisma**: новые поля ожидаются для модерации (approval-состояние) и барахолки (`expiresAt`). Только `prisma migrate dev` в разработке → `scripts/db-migrate.sh` (migrate deploy) на проде. `db push` не используется (и удаляется в P3).
- **Планировщик (P0.1)**: состояние job в SyncState (`job:<name>:*`) — без миграции схемы. Риск: немедленный прогон при старте после долгого простоя отправит напоминания по всем просроченным выдачам разом — это желаемое поведение, повтор не чаще раза в 7 дней сохраняется.
- **Синк (P0.2)**: изменения только в логике merge; риск — регресс покрывается расширенным sync.test.ts. Circuit breaker сохраняется.
- **Прогрев (P0.4)**: фоновая нагрузка на диск/сеть VPS (свободно ~4 ГБ, housekeeping имеет потолок 2 ГБ — снизим для запаса). Прогрев резюмируемый, лимитируемый, переживает рестарт.
- **Прод**: до деплоя каждого P0 — консистентный бэкап SQLite + проверка чтения, `prisma migrate deploy`, health-check, смоук из §11 промта. Rollback: предыдущий релиз + восстановление бэкапа.
