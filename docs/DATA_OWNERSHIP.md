# Источники истины: кто владеет каким полем

Синхронизация с Notion (sync.ts) двусторонняя и раз в 12 часов. До аудита
2026-07-28 upsert слепо перезаписывал локальные данные тем, что пришло из
Notion: выданная книга становилась «свободной», исправленные города обнулялись,
удалённые книги воскресали. Теперь merge идёт по этим правилам — менять их
можно только вместе с этим файлом и тестами в sync.test.ts.

| Поле | Источник истины | Правило синка |
|---|---|---|
| `Book.status` | локальные активные выдачи | книга с активной `Loan.status='active'` остаётся `busy`, что бы ни прислал Notion (у книг там вообще захардкожен `free`); нет активной выдачи — берём статус Notion (у настолок он там ведётся руками) |
| `Book.reviewStatus` | локальная модерация | синк не трогает |
| `Book.active` / `deletedAt` | локальный tombstone | книгу с `reviewStatus='deleted'` или `deletedAt` синк НЕ воскрешает и не обновляет, даже если строка осталась в Notion (архивация могла упасть — её дожимает `flushPending` по флагу `notionArchivePending`) |
| `Book.city/district` | непустое локальное значение переживает пустое из Notion | непустой город из Notion применяется (локальные правки и так уезжают туда через `updateBook`); пустой — не затирает локальный |
| `Book.addedAt` | существующее значение | `null` из Notion (настолки не несут дату) не обнуляет уже сохранённую дату |
| `Librarian.city/district` | непустой локальный backfill | пустое `City/District` из Notion не затирает локальный город владельца (иначе его книги выпадали из городских фильтров) |
| `Librarian.telegram` | локальное значение при `telegramSyncPending` | контакт, ещё не уехавший в Notion, синк не откатывает |
| библиографические поля (`title`, `author`, `genres`, `languages`, `coverUrl`) | Notion | перезаписываются из Notion; локальные правки уезжают туда же через `updateBook` при редактировании |
| книги `source='bot'` без `notionId` | локальная база | синк не видит и не трогает |

Смежные гарантии:

- деактивация «пропавших» строк защищена circuit breaker'ом (`deactivationGuard`);
  упавший или усечённый источник в этом прогоне деактивацию пропускает;
- все запросы к Notion с таймаутом (`NOTION_TIMEOUT_MS`, по умолчанию 30 с) —
  зависший fetch не замораживает синк-цикл;
- второй синк не стартует, пока идёт первый (ручной `/sync` поверх фонового);
- лимит чтения одной коллекции — `NOTION_FETCH_LIMIT` (5000, проверено живым
  запросом: сервер отдаёт честно); упор в лимит без возможности шардирования —
  громкая ошибка, а не молчаливое усечение.
