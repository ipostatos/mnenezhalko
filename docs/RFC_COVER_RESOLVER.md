# RFC: автоматический подбор «красивой» обложки (cover resolver)

Статус: черновик, следующий цикл (после стабилизации аудита 2026-07-28).
Не смешивать с прогревом превью (P0.4, prewarm.ts) — тот ускоряет уже
существующие обложки; этот RFC про то, ОТКУДА берётся хорошая обложка.

## Задача

Пользователь фотографирует свою книгу телефоном. Сегодня это фото и становится
обложкой в каталоге: с бликами, ковром на фоне и под углом. Хочется, чтобы
публичный каталог получал обложку точного издания в хорошем качестве, а фото
служило свидетельством («книга реально стоит на полке») и входом для OCR.

## Принципы

1. **Точное издание, не «похожая книга».** Матчить по ISBN в первую очередь;
   язык, издатель, год и перевод учитываются при сравнении. НЕ подставлять
   обложку другого языка только по совпадению названия — русский перевод и
   польское издание выглядят по-разному, и это видно владельцу.
2. **Уверенность имеет порог.** Высокая уверенность (совпал ISBN или
   название+автор+язык+издатель) — обложка ставится автоматически. Низкая —
   кандидаты показываются пользователю (в мастере добавления) или админу
   (в очереди модерации), никакой тихой подмены.
3. **Фолбэк — облагороженное фото пользователя.** Если официальной обложки
   нет: автоповорот, перспективная выправка по контуру книги, кроп, баланс
   белого — sharp + существующий vision-конвейер это умеют. Фото остаётся
   правдой, просто аккуратной.
4. **Право на исходник.** Пользовательское фото храним (evidence), обложка
   издания — отдельное поле; синк в Notion уносит красивую.

## Источники (в порядке опроса)

| Источник | Что даёт | Ограничения |
|---|---|---|
| OpenLibrary covers | по ISBN, свободно | русские издания покрыты плохо |
| Biblioteka Narodowa | польские издания | только PL |
| Google Books | широкое покрытие, есть ключ (GOOGLE_BOOKS_KEY в проде) | квоты; обложки среднего размера |
| livelib/litres (страница книги) | лучшие обложки русских изданий | нет API — только аккуратный fetch страницы; уважать robots и rate limit, кэшировать навсегда |

## Схема данных

- `Book.coverSource`: `user_photo | resolved | manual`
- `Book.coverCandidates` (JSON, временно): список найденных URL с оценкой
- `Book.coverResolvedAt`

## Поток

1. При добавлении: ISBN известен → прямой lookup (уже есть в isbn.ts) →
   обложка кандидатом с высокой уверенностью.
2. ISBN нет: OCR-поля (title/author/language из vision.ts) → поиск по
   источникам → скоринг кандидатов (совпадение автора, языка, года).
3. Уверенность ≥ порога → ставим; ниже — карточка выбора («это ваша
   обложка?») в мастере/боте; отказ = облагороженное фото.
4. Фоновая догонка: ночной проход по книгам с `coverSource=user_photo`
   бюджетом, как prewarm (те же семафоры и негативный кэш).

## Риски

- Правовой: обложки livelib/litres — использовать только как изображение
  обложки издания (обычная практика каталогов), с кэшем у себя.
- Ложные матчи переизданий: смягчается порогом уверенности и ручным выбором.
- Нагрузка на чужие сайты: бюджеты, per-host лимиты (уже есть в imgcache).
